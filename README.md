# TWM: стенд для станции

Это небольшой интерфейс к **настоящему замороженному runtime TWM** из мастер-архива
`TWM_CURRENT_ARCHITECTURE_MASTER_SNAPSHOT_R13_CANONICAL_POST_AUDIT_R17E1_RECORD_2026-09-23.zip`.
Три модуля нейросети из `VALIDATED_ROLLOUT_R13/FROZEN_PACKAGE/src/` скопированы
байт в байт; шесть checkpoint R12 скопированы из того же frozen package и сверяются
по SHA-256 до загрузки. R13 не добавлял новых весов: он зафиксировал способ
рекурсивного прогнозирования поверх весов R12.

## Что можно увидеть

1. Выберите пример станции с 7–10 узлами или загрузите свои **реальные наблюдения**
   в JSON. История содержит ровно восемь переходов «состояние до → действие →
   состояние после».
2. Выберите действие над узлом и длину симуляции. Belief вычисляется
   нейросетью по восьми наблюдениям. Внутренние классы факторов 0–5 не являются
   понятными человеку названиями законов.
3. Декодер нейросети выдаёт вероятности следующего состояния для всех 36
   сочетаний внутренних факторов. Эти вероятности усредняются с весами learned
   belief. Бинарное состояние получается по фиксированному порогу 0,5.
4. Для следующих шагов модель использует **свои предсказанные состояния** и
   тот же belief. Выдуманные состояния не добавляются в историю наблюдений.
5. Если в примере записан реальный следующий переход **с тем же действием и
   состоянием**, интерфейс покажет сравнение. По кнопке можно принять только
   этот записанный результат как новое наблюдение и пересчитать belief.

Сохранённые примеры — четыре неизменённых ряда из **синтетического** R13
`rollout_fresh.jsonl`, с удалёнными скрытыми метками факторов. «Факт» в
интерфейсе — записанный результат этого синтетического мира, а не измерение
физической станции. Пример не является новым тестом
обобщения. Для другого действия в данных нет факта; интерфейс не изображает
прогноз как действительное событие. Никаких правил скрытой динамики,
генератора мира, исправления ответа или symbolic solver в проекте нет.

**Границы:** это абстрактные бинарные узлы и направленные связи. Натуральный
язык, реальные объекты и полноценный планировщик здесь отсутствуют. Learned
belief может чрезмерно исключать альтернативные гипотезы на неоднозначной
истории; показанные веса не следует понимать как проверенную калибровку.

## Запуск

Рекомендован Python 3.12. В корне проекта:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/streamlit run streamlit_app.py
```

Windows: используйте `.venv\\Scripts\\python` и
`.venv\\Scripts\\streamlit`. Установка CPU PyTorch берёт официальный индекс
PyTorch, указанный в `requirements.txt`.

Прямой запуск того же inference вне Streamlit:

```bash
.venv/bin/python -m runtime.cli --scenario examples/station_8.json --seed 17 --actions 4,4,4
```

Формат собственного файла:

```json
{
  "name": "Моя станция",
  "n_nodes": 7,
  "history": [
    {
      "nodes_before": [0, 1, 0, 0, 0, 0, 0],
      "edges_before": "здесь ровно 42 бинарных числа",
      "action": 2,
      "nodes_after": [0, 1, 0, 0, 0, 0, 0],
      "edges_after": "здесь ровно 42 бинарных числа"
    }
  ],
  "recorded": []
}
```

Пример выше **схематический**: в `history` требуется ровно восемь подряд
идущих переходов, а вместо строк `edges_*` — массивы из `n_nodes ×
(n_nodes − 1)` нулей и единиц. Порядок связей: `0→1, 0→2, ...; 1→0,
1→2, ...`, без петель. Полные пригодные для загрузки образцы есть в
`examples/`. `recorded` необязателен и может содержать до 16 будущих
**наблюдений**, которые никогда не передаются нейросети при прогнозе.

## Проверки и происхождение

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/verify_equivalence.py --archive /путь/к/исходному_мастер_архиву.zip
```

Последняя проверка извлекает **сам исходный** `run_r13.py`, его код модели
и веса во временную директорию. Для четырёх сценариев, трёх seed и двух
последовательностей действий она сравнивает posterior, вероятности каждого
шага и бинарные состояния с вызовом, который использует Streamlit. Численные
вероятности сравниваются с допуском `2e-6`, дискретные состояния — точно.
Архив не входит в небольшой deploy-проект и нужен только для независимой
проверки соответствия. Имена архивных строк, пути и SHA представлены в
`SOURCE_PROVENANCE.json` для аудита; `recorded` и метки строк не передаются
в модель. Код генерации миров и экспериментальные пакеты не включены.

## Публикация в Streamlit Community Cloud

Загрузите **содержимое этой папки** в отдельный GitHub-репозиторий или в
отдельную ветку. В Streamlit Community Cloud выберите репозиторий, ветку и
entrypoint `streamlit_app.py`; при создании приложения выберите Python 3.12.
Зависимости устанавливаются из корневого `requirements.txt`. Веса (около
18 МиБ) должны быть обычными файлами репозитория и оставаться в `weights/`;
Git LFS здесь не нужен. После сборки сначала запустите архивную проверку
эквивалентности локально или в среде с исходным архивом. Стенд не использует
секреты, API или подключение к базе данных.
